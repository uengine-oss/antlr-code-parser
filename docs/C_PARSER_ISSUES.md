# C 파서 작업 기록

## 우리가 한 일

C 소스코드(.c, .h 파일)를 읽어서 "이 파일에 어떤 함수, 구조체, 변수가 있는지" JSON으로 정리하는 파서를 만들었다.

---

## C는 왜 어려웠나

Java 코드는 보이는 그대로 읽으면 된다.
C 코드는 보이는 것과 실제가 다르다.

예를 들어 이런 코드가 있다:

```c
#define MAX_PHONE 20

char phone[MAX_PHONE];
```

사람 눈에는 `MAX_PHONE`이 `20`이라는 게 보인다.
하지만 파서는 `#define` 줄을 무시하기 때문에 `MAX_PHONE`이 뭔지 모른다.
그래서 `char phone[MAX_PHONE]`을 읽다가 에러가 난다.

왜 `#define`을 무시하냐?
우리가 쓰는 ANTLR C 문법 파일(`CLexer.g4` 725번째 줄)에 이렇게 써있다:

```
"#으로 시작하는 줄은 무시해라"
```

이건 버그가 아니다.
**"누군가 미리 `MAX_PHONE`을 `20`으로 바꿔놓을 거야"라고 가정**하고 만든 문법이다.
실제 C 컴파일러(gcc)도 코드를 읽기 전에 먼저 이런 바꿔치기를 한다.

그래서 **우리도 파싱 전에 바꿔치기를 해줘야 한다.**

```
우리가 하는 일:

1. MAX_PHONE이 20이라는 걸 미리 파악
2. 코드에서 MAX_PHONE을 20으로 바꿈
3. 바뀐 코드를 파서에 넘김
```

이게 C 파서 작업에서 가장 핵심적인 부분이다.
아래 문제들도 전부 이런 "파서가 모르는 정보를 미리 알려주는" 패턴이다.

---

## 문제 목록

---

### 문제 1: 숫자 상수를 모른다

코드에 `#define MAX_PHONE 20`이라고 써있는데 파서가 무시해서 모른다.
`char phone[MAX_PHONE]`에서 에러 → 구조체 전체가 깨짐 → JSON에서 누락.

해결: `MAX_PHONE`을 `20`으로 바꾼 다음에 파서에 넘긴다.

---

### 문제 2: Windows/Linux 코드가 겹친다

```c
#ifdef _WIN32
    Windows용 코드
#else
    Linux용 코드
#endif
```

파서가 `#ifdef`를 무시하니까 두 코드가 동시에 보여서 에러.

해결: 하나만 남기고 나머지를 지운다.

---

### 문제 3: 사용자가 만든 타입을 모른다

```c
TPConfig *config;
```

파서가 `TPConfig`이 타입 이름인지 일반 변수인지 구분을 못한다.

해결: 코드를 미리 훑어서 `typedef`로 만든 이름들을 모으고, 파서에게 "이건 타입이야"라고 알려준다.

---

### 문제 4: 표준 타입을 모른다

```c
int64_t id;
FILE *fp;
HANDLE thread;
```

`int64_t`, `FILE`, `HANDLE` 같은 건 C 표준이나 운영체제가 제공하는 타입인데
파서가 모른다.

해결: 자주 쓰는 타입을 미리 등록해놓는다.

---

### 문제 5: 구조체 이름을 못 찾는다

```c
typedef struct {
    int id;
} Subscriber;
```

파서는 이 코드를 읽을 수 있는데, `Subscriber`라는 이름이 예상과 다른 위치에 들어간다.
우리 코드가 원래 위치에서만 찾으니까 못 찾는다.

해결: 원래 위치에 없으면 다른 위치도 찾아보도록 했다.

---

### 문제 6: 리턴 타입에 "static"이 섞인다

```
원래: static void func()
결과: returnType = "staticvoid"     ← void만 있어야 하는데 static이 붙음
```

해결: static은 따로 빼고, void만 리턴 타입으로 넣는다.

---

### 문제 7: 모든 곳에 포인터(*)가 붙는다

```
원래: int func()
결과: returnType = "int *"          ← 포인터가 아닌데 *가 붙음
```

포인터가 있는지 확인하는 코드에 버그가 있었다.
"비어있는 리스트"를 "있음"으로 잘못 판단했다.

해결: 리스트가 진짜 비어있는지 확인하도록 고쳤다.

---

### 문제 8: 함수 선언이 변수로 잡힌다

헤더 파일에 있는 `int func(int a, int b);` 같은 함수 선언이 변수로 분류됐다.

해결: 괄호 안에 매개변수가 있으면 함수로 판별한다.

---

### 문제 9: 타입 이름의 공백이 사라진다

```
원래: struct tm
결과: "structtm"                    ← 공백이 없어짐
```

해결: 원본 텍스트를 그대로 가져오는 방식으로 변경했다.

---

### 문제 10: 파일 설명 주석이 함수에 붙는다

파일 맨 위에 있는 설명 주석이 첫 번째 함수의 주석으로 들어갔다.

해결: 주석과 함수 사이 거리가 멀면 관련 없는 주석으로 판단한다.

---

### 문제 11: 주석이 엉뚱한 곳에 붙는다

```c
ACTIVE,      /* 정상 */          ← 이건 ACTIVE의 주석
SUSPENDED,   /* 일시정지 */       ← 이건 SUSPENDED의 주석
```

`/* 정상 */`이 ACTIVE가 아니라 SUSPENDED에 붙어버렸다.

해결:
- 이전 줄 끝의 주석은 다음 줄에 안 붙도록 했다
- 같은 줄 뒤의 주석을 찾는 기능을 추가했다

---

### 문제 12: 바이너리 파일 에러

`.dat` 같은 바이너리 파일을 텍스트로 읽으려다 에러.

해결: 읽기 실패하면 건너뛴다.

---

## 전체 흐름

```
1. 준비
   - 헤더 파일에서 숫자 상수 수집 (MAX_PHONE=20 같은 것)
   - 소스 파일에서 타입 이름 수집 (Subscriber, Plan 같은 것)

2. 파일마다 반복
   - 숫자 상수 바꿔치기 (MAX_PHONE → 20)
   - Windows/Linux 중복 코드 정리
   - ANTLR 파서로 코드 분석
   - 함수/구조체/변수를 JSON으로 만듦
   - JSON 파일 저장
```
